# Core pages and retention continuation

Local only; no deployment, DNS, push, live enquiry, deletion or remote CMS write.

## Implemented

- Static /services directory links all eight revised services, making them
  discoverable from the global footer rather than orphan local URLs.
- Retained /about, /contact and /faqs URLs now contain confirmed-scope copy,
  canonical metadata, noindex and honest contact fallbacks. No unsupported
  qualifications, testimonials or appointment receipts were introduced.
- Shared server-rendered information template uses the accepted cream/teal
  shell, semantic headings, breadcrumbs and responsive service-card grid.
- Global footer links services, guides, about, contact and FAQs. The approved
  homepage and both 16-question sample journeys remain unchanged.
- Static paths are reserved from the legacy dynamic CMS renderer and omitted
  from its generated parameters. This deliberately replaces the matching old
  CMS page presentation; remote records and source exports are untouched.
- Retention decision completed: 90 days from first receipt, unsuccessful only.
  Pure local eligibility function and 25 synthetic checks added. No deletion
  job, storage read or active policy was introduced.

## Verification

- Lint, standalone typecheck and both optimized offline builds pass; 26 static
  pages generated by each build.
- Shell tests now 32; route tests 72 (four paths now statically owned), page-body
  tests 60 and retention 25. Other numbered synthetic tests unchanged.
- Opt-in check-local-http.mjs passes 1,401 assertions on each local server:
  22 pages, headings, canonicals, noindex, internal routes/fragments, normal-mode
  lack of inputs, sample-only forms, robots disallow and held wardrobe 404.
  These are repeated HTTP/DOM assertions, not 2,802 distinct user scenarios.
- Browser: Services screenshot inspected, directory-to-plumbing navigation
  works, no new console errors observed; sample homepage refreshed successfully.
- Mobile viewport override returned unchanged desktop dimensions even after
  reload. It was reset; a 375px browser verification is NOT claimed. Responsive
  visual verification remains outstanding rather than marked passed.

The browser-verification CLI was unavailable; supported browser controls were
used instead. Next.js/React guidance kept the new pages server-rendered with
metadata, semantic links and no new client dependencies.
